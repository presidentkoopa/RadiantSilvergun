NOTE ON THE SMOKE FOLDER'S EXTENSION-LESS FILES
  The brief warned the SMOKE folder is full of extension-less files. It is --
  but the large majority are MISLABELLED PNGs, not Doom lumps, and the Read
  tool renders them fine. Only 4 SMOKE sequences are true Doom format
  (BSP4, PUF2, PUF3, VFX3), and PUF2/PUF3 also ship .png siblings, so only
  BSP4 and VFX3 were genuinely unviewable in SMOKE.

NOTE ON "DUPLICATE" FILE PAIRS
  PUF2, PUF3: each frame exists twice -- once as a raw Doom lump, once as a
  .png of identical dimensions. Genuine format duplicates. Use the .png.
  SMOK: NOT a format duplicate. The extension-less SMOK* files are 56x56 and
  the SMOK*.png files are 141x130 -- two completely different smoke sequences
  colliding on one name. Both are catalogued separately below. This is a
  naming hazard for any import script.

DUPLICATE CHECK vs RS_MAIN  (E:\RS_Main\sprites\combatfx\)
================================================================================
Method: MD5 over all 597 ART SOURCE files vs all 453 RS_Main combatfx files
(catches exact copies regardless of format), plus a decoded-pixel hash pass
(catches re-encoded copies), plus targeted alpha-silhouette comparison for the
smoke families. Caveat: the pixel pass could not decode 131 of 597 ART files
(malformed-but-renderable PNGs), so the pixel pass alone has blind spots -- but
the MD5 pass covered every file, so exact duplicates below are complete.

EXACT (byte-identical) DUPLICATES -- do NOT re-import:
  vfx/LLIT        -> combatfx/lightning/RSL0     11 of 11 frames
  vfx/LRVV        -> combatfx/lightning/RSL1     25 of 25 frames
  vfx/LTHN        -> combatfx/lightning/RSL2     13 of 13 frames
  SMOKE/SMKE      -> combatfx/smoke/RSK1         18 of 18 frames
  SMOKE/SMKE      -> combatfx/smoke/RSK2         11 frames (partial subset)
  PARTICLES/PBAL  -> combatfx/plasma/RSP7         5 of 5 frames
  PARTICLES/TRAC  -> combatfx/projectiles/RSR6    all rotations
  PARTICLES/TRAC  -> combatfx/lightning/RSL4      all rotations (imported twice)
  PARTICLES/BPUF  -> combatfx/puffs/RSU1          4 of 4 frames

PARTIAL DUPLICATES -- RS_Main holds only a slice; the full sequence is richer:
  PARTICLES/SPKS  -> combatfx/sparks/RSS2   RS_Main has 2 frames of 15.

================================================================================
GAPS, HAZARDS AND HONEST CAVEATS
================================================================================
* 6 sequences could not be viewed and have NO description: BSP4 (26 frames),
  VFX3 (10), BPRT (8), SHOQ (7), WOOD (4) are raw Doom picture lumps; BUBL (2)
  is a corrupt PNG. Together that is 57 frames of unknown content. Converting
  the 5 Doom lumps with SLADE or a lump-to-PNG tool would close this gap.
* NAME COLLISION: SMOKE/SMOK is two different sequences under one name (56x56
  raw vs 141x130 .png). Any import script keyed on the 4-char name will silently
  merge or overwrite them.
* CASE HAZARD: SMk2, PBALc0, SPKOb0, SPRKo0/SPRKs0 use lowercase characters
  where Doom convention expects uppercase. Case-sensitive tooling will miss them.
* SPRK has NO alpha channel (opaque black background) -- requires additive
  blending or it renders as a black square.
* PBAL, GLOW, SPKO and TRAC are NOT animations. PBAL/GLOW/SPKO are colour sets
  and TRAC is an 8-way rotation set. Playing them as animation frames will look
  wrong. This is the single most likely mistake an automated importer would make.
* TI3R is a bitmap font, not an effect, despite living in the fx folder.
* SMK3 and SMK6 are visually redundant with each other (verified as separate
  files by checksum, but the same effect). Pick one.
* 131 of 597 ART SOURCE files are malformed enough that the Python imaging
  library refuses them, though the image renderer displays them. Any conversion
  pipeline should expect decoder failures and handle them rather than aborting.
