log from a real engine boot (QZDoom g4.15pre, E:\UZDXREMA build), and the engine

## 2. CRITICAL BUGS (game-breaking, all in non-sacred files)

### C1. Sixty GH weapon classes are bricked — including the Vanilla+ starting offhand
`RS_GH_Ammo.zs:6-77`. Every `*Loaded2..6` inherits from `*Loaded`. Engine ammo
rules (`ammo.zs` GetParentAmmo/HandlePickup/CreateCopy) resolve derived ammo to
the parent class, so a reload into `PistolLoaded4` credits identity 1's magazine
— forever. The gun arrives empty, Fire falls into Reload, each pull eats up to a
full magazine of reserve, and it never fires. Live from the first second of a
Vanilla+ run (`RS_GH_Pistol4` starting offhand) and on every GH elite drop of
identities 2–6. Identity-1 weapons work — which is why the mainhand pistol fires
fine in play. The VR_ set is immune; `RS_Ammo.zs:12-15` documents the exact rule
GH violates.
**Fix:** reparent all 60 Loaded2..6 classes directly to `Ammo`. One file,
mechanical.

### C2. The Dual_X freeze is still live — all three re-entrancy guards protect a window the event never arrives in
`RS_ClassGating.zs:50,107,145,203,239` (`mFilling`) and `RS_EliteDrop.zs:88-94`
(`mSpawningDrop`). Both were built on the belief that `Actor.Spawn` fires
`WorldThingSpawned` synchronously. Engine source says it is **deferred** to the
fresh-thinker pass (`p_mobj.cpp:5164`, `dthinker.cpp:152-160,602-611`) — the
event arrives after the guard is already cleared. Verified independently by two
agents. Consequences:
- **Pedestal fill loop:** replacement spawns replacement forever inside one tic
  → hard freeze at map load on any Dual_X class near a weapon pickup.
- **TryRandomBFG:** output set == input set → destroy+spawn forever → OOM. This
  matches the "could not malloc 2264 bytes" in commit `afc9f174` — whose own
  message admits "NEITHER LIVE BUG IS CONFIRMED FIXED... those tests never
  loaded a map."
- **Elite payload:** the exemption window closes before the payload's event
  arrives, so elite drops on Dual_X feed the same freeze.
**Fix:** identity-based exemptions, not time windows. Skip a pickup that already
IS one of the player's identity classes (fill becomes idempotent); handler-held
reference list for swaps/RandomBFG; the elite payload already carries
`bNoInteraction` by event time and can be recognized by state.

### C3. The MeatGrinder heavy line deals zero or vanilla damage; GH grenades ignore stats
`RS_Weapon.zs:1006-1036` — `RS_FireProfileHeavy`'s hardcoded `is` chain knows
only `RS_Enhanced*` and three GH energy classes. Not in the chain, though each
defines an uncalled `SetupStats`: `RS_PS_Rocket` (**no Default Damage — direct
hits deal 0**; splash-only, so it **cannot hurt a Cyberdemon or Mastermind at
all**), `RS_PS_BFGShot` (ball deals 0), `RS_PS_PlasmaShot` (vanilla 5 at every
tier), `RS_GH_GrenadeLaunched/Thrown` (tier/rolls decorative; also explodes
invisibly — Death state is all TNT1).
**Fix:** extend the dispatch (or make it data-driven — an interface/mixin so the
class of bug ends, not the instance).

### C4. Heavy and melee damage is double-multiplied by the engine
- `RS_FX_HeavyProjectiles.zs:85` — SetupStats sets rolled damage but never
  defeats the engine's `random(1,8)` missile multiplier (`p_map.cpp:1430`). A
  Basic rocket rolling 80–140 lands **80–1120** direct; splash ~4–7× vanilla,
  self-splash included. The bullet path defeats exactly this
  (`RS_FX_BallisticFired.zs:168-171`); heavy forgot.
- `RS_Weapon.zs:705` — melee calls `A_CustomPunch(dmg, false, ...)`;
  `norandom=false` multiplies by random(1,8) **after** Condition/crit/keywords.
- Same defect in affix parts: swarm motes `Damage 4` → 4–32, nova beads
  `Damage 5` → 5–40 ×16 beads (`RS_FX_AffixParts.zs:418,524`), against
  "fixed and small ON PURPOSE" comments.
**Fix:** one contract — DamagePerShot is what lands. ExactDamage/DoSpecialDamage
on heavies, `norandom=true` on melee.

### C5. Offhand semi-autos are full-auto (and jam while the main trigger is held)
`RS_Weapon.zs:398` — the trigger gate tests `BT_ATTACK` for both hands; offhand
fires on `BT_OFFHANDATTACK` (`player.zs:463-479`). Held offhand trigger =
machine-gun revolver/launcher/BFG; held MAIN trigger = offhand fires once and
locks. Same wrong-button test breaks the AllClear beep offhand
(`RS_Weapon.zs:265`).
**Fix:** `int bt = invoker.bOffhandWeapon ? BT_OFFHANDATTACK : BT_ATTACK;` — two
sites.

## 5. WHAT WORKS — and it's the majority

**The weapon core** (`RS_Weapon` + AttackProfile/Catalog/Keywords) is the best
system in the mod. Every gun fires through one dispatcher; attack rotations are
data; the keyword firewall (BASE identity vs granted) exists because of a real
bug and prevents its recurrence; ammo affordability, backfire, crit-per-pull,
choke/cadence all resolve in one place. Empty slots can't detonate. The 655-line
Streak beam math was audited hard and is *correct*.

**Hand seating** (`SeatHands`) is verified correct for all 9 classes, spawn and
respawn, engine-checked (`WP_NOCHANGE + BringUpWeapon` raises both hands in one
tic). Both hands can never end empty. `RS_OffhandSeat` is correctly parked —
superseded and buggier than its replacement.

**The elite system**: 14 of 17 type controllers verified WORKS line-by-line
(C08/C10/C11 the exceptions above). The lifecycle — mark at spawn, boost, reveal
at 50%, full heal, controller wake, death, restore-stats-so-raises-can't-compound
— is coherent, and the archvile-resurrection path is handled at three layers.
All 17 weight cvars resolve. One-shot-from-full-HP pays nothing *by contract*
(unrevealed = no payout), which is a design question, not a bug.

**The drop pipeline** is genuinely clever: a real rolled weapon instance parked
outside the pickup path as its own pedestal, a tier-tinted beam, a proximity
triptych that hinges like a real triptych, hand-pose rays with poke and punch
detection, and take-by-pointing-hand seating. The scope-split (WorldTick
geometry → drop handler letterbox → PlayerThink capture, because WorldTick is
too late to eat a button) is documented correctly in the panel lane — the ONE
place in the repo where the engine-order lesson is right.

**Scoring**: all 15 bonuses reachable (Switcharoo's offhand blindness aside),
every cvar declared, every HUD asset on disk, canvas dims exact.

**GunBonsai integration**: XP attribution by declaration (not detection) is the
right call; promotion/GB levels cannot desync (verified one-directional); XP is
never lost or double-counted; the card picker with reroll/expand/promote and
Esc-banking is a real improvement over stock.

**ReserveSquads** is coherent and ship-ready behind its OFF cvar — validated
placement, elite coupling read-only, public API awaiting a caller.

**NoHitscan** substitution preserves damage fidelity properly (per-pellet events,
victim factors once, blood/decals/switches reproduced).

**The monster tree — the "is it cool" answer: yes.** Top-decile for the genre.
Zero flattened damage rolls in the fidelity sample; provenance discipline
("every actor cites its CH line, every strip keeps the original as a comment")
better than anything the reviewer had seen shipped; the cyberdemon header
resolves CH's own ACS bugs from source — archaeology, not transcription. The
honest criticism: it is copy-paste sprawl *by policy* — "a mirror with excellent
footnotes, not an original composition" — which was the assignment. The 4,100
deprecation warnings should be LEFT ALONE: `A_CustomMissile` deliberately
preserves an old pitch bug (`CMF_BADPITCH`) that CH tuned all 3,322 sites
against; conversion is the trap.

## 6. TOUGH LOVE — the "listen bucko" section

You asked for it straight, so:

**Half your systems are ideas wearing code.** PACK cards: 965 lines, zero
consumers — that's not a system, it's a diorama of one. Repair: the entire
Grey Bits economy has no cash register — currency accumulates against a vendor
that was never built. Promotion curses: stubbed to `return`. Player XP: a
progress bar to a door that isn't there. ElitePackage: built, dormant, called by
nothing. The wheel: a PoC whose core premise (WorldTick input capture) is
backwards, shipping on the V key. SystemsMaster: a contract zero monsters
signed. That is SEVEN parallel half-systems. Any two of them finished would do
more for the game than all seven at 60%.

**Your three weapon sets are one real arsenal and two liabilities.** The VR_ set
is hand-built, stat-rolled, animation-exact — it's the game. The GH set is a
templated import whose template bricked 60 of its own classes and whose grenades
explode invisibly with unrolled stats. The PS set's heavy weapons deal zero or
vanilla damage. Either these sets get the same per-weapon care the VR_ set got,
or they're bulk that dilutes testing and doubles every future bug surface.
Pandemonia does "what you do, more smartly" in exactly one way: it has ONE
weapon roster and every gun in it is finished.

**The menu is writing checks the code can't cash.** 227 exposed cvars, and the
audit found the rows players are most likely to touch — tier bonus, giant slayer
tier, HQ sounds, ricochet FX — do nothing. A 40-option menu where everything
works beats a 227-option menu where you can't tell. Meanwhile genuinely
gameplay-changing systems (NoHitscan, ON by default!) have no menu presence at
all.

**What's genuinely great and deserves the focus:** the elite→reveal→pedestal→
triptych→take loop is a real, original game loop — nothing in the Doom mod space
does diegetic loot cards with hand-pose interaction. The weapon core's
profile/keyword architecture is genuinely extensible — affixes writing keywords
that the dispatch reads fresh every pull is the right design. The condition/
backfire texture, the cadence beep, promotion-as-reset — that's a coherent
roguelite identity. And the monster port is museum-grade. **The game inside this
repo is: VR_ arsenal + elites + drops + promotion + condition + score, on the CH
bestiary.** Everything else is either support for that loop or a distraction
from it.
