Session Handoff -- PACK / Affix System -- 2026-08-03

WHAT THIS SESSION BUILT
================================================================================
PACK (Profile Attack Content Kreation): weapon attacks assemble from
RS_Catalog parts; affixes now assemble themselves from a priced ingredient
pool instead of being hand-authored one class at a time.

Real, working, end to end:
  RS_FamilyPalette      archetype -> eligible catalog slice (Bullet+Heavy)
  RS_KeywordEffects      -> RS_ShotKeywordMods.Resolve(wpn, profile), ONE
                          resolved bundle (dmg/pellet/spread/vel mults +
                          homing/piercing flags), replacing the old two-
                          out-param functions. Axes: payload (multi/
                          cluster/slug, real math), behavior (homing +
                          piercing, both native GZDoom), drawback
                          (sluggish/wild -- negative-cost budget fuel).
  RS_AffixIngredients    the parts bin for AFFIXES. Each ingredient has a
                          PowerCost (0=wash, + =bonus, - =downside) and
                          eligibility gates: MinPelletCount, MinTier,
                          RequiredArchetype, RequiredModeMask (new --
                          stops a drawback that's a no-op on some weapon
                          from handing the generator free budget).
  RS_AffixGenerator      picks eligible+affordable ingredients, provably
                          never nets positive cost. Generate()/Apply()
                          split so a bundle can be inspected before it
                          touches a real weapon.
  TFLV_Upgrade_RS_Assembled  the real in-game connector -- calls Generate()
                          once (cached, idempotent per BaseUpgrade's own
                          contract), Apply()s it, ungrants on deactivate.
  Affix part-override layer (RS_Weapon.zs)  Affix* fields (Projectile/
                          FireSound/ImpactPuff/Sparks/Smoke/Trail/
                          ExplosionVisual/Casing) -- the "part-swapper"
                          affix category, previously impossible. Real
                          precedence: affix > profile > weapon > default.
                          Mode-fenced (a ballistic class offered to Heavy,
                          or vice versa, is refused, not spawned broken).
  rs_gb_legacy_affixes    cvar gates the vendored ~50-60 stock GunBonsai
                          upgrades off by default; RS-authored affixes
                          (rs_upgrades/) always active. One choke point:
                          TFLV_Upgrade_Registry.IsRSAllowed().
  Heavy-mode parity       pellet loop + homing now reach Rocket/Plasma/BFG,
                          not just Bullet mode.
  docs/rs_MASTER_FX_CATALOG.txt  protected (see CLAUDE.md), stats-block
                          updated for the ART SOURCE inventory (~743
                          sequences catalogued by actually viewing frames),
                          but Sections 1-6 are NOT YET MERGED IN -- the
                          five source reports exist in this session's
                          scratchpad, never got written into the doc.

KEY DESIGN RULES (see CLAUDE.md, already durable)
================================================================================
  - An affix may REDISTRIBUTE along an axis a mechanic already owns
    (Promotion owns pellet growth) but never GROW it for free. Enforce
    with an eligibility gate, not a price tag, where the math can't do it
    alone (slug requires PelletCount >= 2).
  - null is a crash-safety net, never a design choice -- a profile
    leaning on every default at once is hollow, not valid.
  - Look at the sprite. Filenames in this project's art libraries lie.

REAL GAPS, HONEST, ORDERED BY WHAT MATTERS
================================================================================
1. RS_AffixIngredients.zs has the MECHANISM for piercing/sluggish/wild
   (resolver + mode-mask gate both exist) but the pool itself still only
   has the original 4 entries (multi/cluster/slug/homing). Adding the new
   ones is the very next small task.
2. GunBonaiSockets (rolled, stored per weapon) is READ BY NOTHING. A
   Basic-tier weapon can take GunBonsai affixes today, which the
   project's own design doc (rs_00) explicitly forbids. Real divergence,
   not yet fixed.
3. Master FX catalog merge is data-ready, not done -- five inventory
   reports sit in scratchpad, never written into rs_MASTER_FX_CATALOG.txt
   Sections 1-6.
4. element: keyword axis (thermal/corrosive/shock/plasma/void) has ZERO
   wired effects. The ART SOURCE inventory found ready-made color-variant
   families (fire in 3 colors, smoke in 4+, flares in 3+) that make this
   cheap once picked up.
5. Melee mode is the thinnest PACK target -- only damage multipliers
   reach it, no palette fencing, no melee-flavored ingredients.
6. No real part-swap affix exists yet to prove the new Affix* override
   layer end to end (Twin Barrel proved the keyword-grant layer; nothing
   has proven the part-swap layer the same way).
