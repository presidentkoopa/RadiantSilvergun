WHY THIS EXISTS
================================================================================
PACK (Profile Attack Content Kreation) assembles weapon attacks -- and
eventually weapon NAMES -- by picking parts from a catalog. To pick a part, the
generator has to know what parts exist. To name a weapon after its parts, it has
to know what each part LOOKS like.

Code can't answer either question. RS_Catalog.zs returns class names
("RS_BallisticType1"), not descriptions. Sprite filenames are cryptic and
actively misleading (RVFB/RVFG/RVFR were once assumed to be revolver muzzle
flashes on name pattern alone -- they were voxel-pack content, completely
unrelated). The only reliable way to know what a sprite sequence is, is to
LOOK at it.

This file is the result of looking. Every VISUAL line below was written from a
rendered frame, not inferred from a filename.


HOW TO READ AN ENTRY
================================================================================
    SEQUENCE      4-character Doom sprite name. Frames are the 5th character
                  (A, B, C...), rotation the 6th (usually 0 for effects).
                  So sequence "RSE0" with 26 frames = RSE0A0 .. RSE0Z0.
    FRAMES        how many animation frames
    SIZE          pixel dimensions
    VISUAL        what it actually looks like, from viewing it
    FLAVOR        words usable in a generated weapon name (Borderlands-style
                  prefix/suffix -- see docs/rs_05_bullet_attack_pack.txt)
    USE           which PACK ingredient slot(s) it can fill
    STATUS        IN-REPO (already in sprites/combatfx/) or
                  AVAILABLE (in ART SOURCE, not yet imported)


RELATIONSHIP TO THE REST OF THE PROJECT
================================================================================
    This file (docs/)            -- WHAT EXISTS and what it looks like.
                                    Human-readable. The source of truth for
                                    descriptors and flavor words.

    RS_Catalog.zs               -- weapon-side code. Returns class names for
                                    projectiles/puffs/sparks/trails/sounds.

    RS_MonsterCatalog.zs        -- monster-side equivalent. Summon rosters,
                                    satellites, monster projectiles.

    sprites/combatfx/           -- the actual imported sprite files.

    An entry here does NOT imply a class exists for it. Most AVAILABLE entries
    have no code behind them yet -- that's the point, this is the menu we build
    from.
