--------------------------------------------------------------------------------
WHAT LIVES IN THE HANDLER, NOT IN THE PROFILES
--------------------------------------------------------------------------------

  No profile touches the monster's OWN projectiles from its controller. Four
  effects are applied by handler.txt's WorldThingSpawned instead:

    DARKGREEN  every missile gets champion_DarkGreenMissileCreep, or
               champion_RedMissileCreep if transformed. handler.txt:331-339,
               gated on cvar champion_ProjectileCreep.
    WHITE      every missile gets champion_WhiteMissileCreep. :341-348
    YELLOW     A_ScaleVelocity(1.5), or 2.0 when ld_boost and transformed.
               :362-366.  Yellow's own file has no projectile code at all.
    INDIGO     missiles from CloneToken holders get Scale *0.75 and
               A_ScaleVelocity(0.75). :350-354

  Plus a cosmetic champion_MissileEffect glow on all champion missiles when
  champion_MissileColours is on, handler.txt:301-329.

  THIS IS WHY OUR HOOK LIST HAS OnMissileSpawned. There is no virtual for it
  in the source; the handler hardcodes four branches. Ours gets a hook.

--------------------------------------------------------------------------------
FACTS THAT WILL BITE THE PORT
--------------------------------------------------------------------------------

  * 22 `static const TYPE name[] = {...}` SITES. Six at class scope, sixteen
    inside GetParticleColour. Full list in rs_25 H1. None of them compile
    reliably here. champion_Tokens[] (the mod's zscript.txt:112) is indexed
    by ALL SEVENTEEN profiles, so it is the first one to replace.
  * FOUR PROFILES HAVE NO REVEAL BONUS: Black and Bronze override
    champion_LegendoomSpecial with an EMPTY body; Grey and Red do not
    override it at all. DarkRed reads `transformed` inline instead. If our
    OnReveal is empty for those four, that is correct, not missing.
  * FOUR PROFILES NEVER TICK: Black, Indigo, Orange and Red never set eftic,
    so champion_TickEffect cannot fire for them at all -- baseclass.txt:358
    gates on eftic being non-zero. None of the four overrides TickEffect
    either, so this is consistent, not a bug in the source.
  * TWO MUTATION EXCLUSIONS ARE REAL RULES: Undying refuses DarkRed
    (baseclass.txt:209), Ghost refuses Pink (baseclass.txt:222).
  * THREE PROFILES SUPPRESS PARTICLES ENTIRELY by overriding
    champion_SpawnParticles empty: Bronze, Gold, Silver.
  * DEAD CODE NOT TO PORT: champion_BigDarkGreenCreep (referenced only inside
    a comment, defined nowhere), Pink's HealingCross/Resurrection/HealingRing,
    Silver's Shield/Reflection/ReflectionGiver/SparkleRing, and the second
    string argument to champion_SpawnIcon.
  * SPECIES 'succ' -- Champions stamps it on the player (handler.txt:295) so
    Cyan's and Silver's A_RadiusThrust can filter. We need our own equivalent
    or those two throw the player around. The 03 hotfix at champ_cyan.txt:55
    was fixing exactly this.
