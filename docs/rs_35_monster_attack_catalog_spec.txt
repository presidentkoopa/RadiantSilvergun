================================================================================
   RS_35 -- THE MONSTER ATTACK CATALOG: FORMAT SPEC
   2026-08-06. Written before any family was catalogued, so that seventeen
   passes produce ONE vocabulary instead of seventeen.
================================================================================

WHY THIS EXISTS, IN ONE SENTENCE
--------------------------------------------------------------------------------
Every monster attack becomes a thing a PLAYER WEAPON can wear -- an
RS_AttackProfile a slot can hold -- so the arsenal's variety stops being
limited to the eight monster rounds somebody hand-typed into
rs_fx_affixparts.zs.

This is a PARTS BIN, not documentation. If a row cannot be turned into a
factory call without opening the monster file again, the row is wrong.


THE MEASURED SHAPE OF THE JOB
--------------------------------------------------------------------------------
  251 monsters carry attacks, across 17 families.
  398 attack states by label count.
  ~3,590 attack CALL SITES -- which is not the row count. The Frost Imp's
  ice fan is ELEVEN A_CustomMissile lines and ONE attack. Rows collapse
  hard; expect a few hundred, not thousands.

  A NAME FILTER DOES NOT FIND THEM. The Frost Imp's fan lives in a state
  called `IceWeave`, reached by A_JumpIfCloser from Missile. A scan for
  `Missile:` / `Melee:` found 215 of 398 and silently dropped the rest.
  FOLLOW THE JUMPS. An attack is any state chain reachable from Missile,
  Melee, or a Pain/Death/See beat that fires something.


================================================================================
1. WHAT ONE ROW IS
================================================================================

One row = one ATTACK a player would recognise as a single thing that
happens when the monster attacks.

  * The 11-line ice fan is ONE row.
  * `OtherB` -- the same fan mirrored, reached by A_Jump(128) -- is NOT a
    second row. It is the same attack with `mirrored: yes`.
  * A state that only picks between two attacks (A_Jump, A_JumpIfCloser)
    is not a row; it is the range band / weighting on the rows it reaches.
  * A monster with a close attack and a far attack has TWO rows.


================================================================================
2. THE ROW FORMAT
================================================================================

One block per attack. Field order fixed. Omit no field -- write `--` when
a thing genuinely is not there, because blank and absent must not look the
same (that mistake is the entire reason RS_35 exists; see rs_05).

  ATTACK   <MonsterClass>.<StateLabel>
  file     <path:line of the first attack line>
  shape    <one word from section 3>
  payload  <projectile class>  x<count>   [+ secondary payloads]
  arc      <degrees, or -- for a single>
  timing   <tic list, or "one tic">
  damage   <DamageFunction / Damage as written -- NEVER flatten a roll>
  type     <DamageType, or -- >
  sound    <what the ATTACK itself plays, or -- >
  impact   <what the payload does on arrival: puff class, spawns, sound>
  trigger  <Missile | Melee | Pain | Death | XDeath | Walk | Spawn>
  range    <MinRange..MaxRange if gated by A_JumpIfCloser etc, else -- >
  mirrored <yes | no>
  inherit  <parent class, if the payload's Death/sound comes from a parent>
  profile  <the RS_AttackProfile factory call this becomes>
  notes    <anything that would be lost otherwise>

THE `profile` LINE IS THE POINT. It is the deliverable. Example, from the
Frost Imp, fully worked:

  ATTACK   RS_CyanImp2.IceWeave
  file     zscript/monsters/imp/RS_Imp.zs:421
  shape    FAN
  payload  RS_FrostLong2 x11
  arc      20   (-10..+10, even 2-degree step)
  timing   3,2,3,2,3,2,3,2,3,2,3   (28 tics total)
  damage   DamageFunction (random(3,9))
  type     Ice
  sound    --   (fires SILENT; the cyan ball variant plays "imp/attack")
  impact   PUFI A-H frost puff + DeathSound "Ice/Hit2" -- BOTH INHERITED
  trigger  Missile   (via A_JumpIfCloser(600) from Missile)
  range    ..600
  mirrored yes  (OtherB runs +10..-10 with A_SetScale(-1.0,1.0))
  inherit  RS_FrostLong  (child strips +SEEKERMISSILE, overrides Spawn only)
  profile  MakeBurst(proj:"RS_FrostLong2", count:11, delayTics:3, arc:20)
  notes    Uneven ripple 3/2 has no exact form -- BurstDelayTics is uniform.
           3 tics = 33 total vs CH's 28. Recorded, not silently rounded.


================================================================================
3. THE SHAPE VOCABULARY -- CLOSED SET. DO NOT INVENT A NEW ONE.
================================================================================

Derived by surveying the tree before writing this. If an attack genuinely
fits none of these, write `shape UNCLASSIFIED` and describe it in `notes`;
do NOT coin a word. Coined words are what make seventeen files not compose.

  SINGLE     one projectile, aimed.
  FAN        n projectiles, stepped angles, fired together or nearly.
  BURST      n projectiles, SAME angle, spaced in time.
  SALVO      n projectiles on one tic (a shotgun of a thing).
  RING       n projectiles across a full 360 -- random(0,359) is the tell.
  SCATTER    n projectiles at random angles inside a cone.
  MELEE      A_CustomMeleeAttack / A_MeleeAttack.
  HITSCAN    A_CustomBulletAttack / A_FireBullets.
  CHARGE     A_SkullAttack -- the monster IS the projectile.
  VILE       A_VileAttack -- line-of-sight burn, no travel.
  COMBO      A_CustomComboAttack -- melee if close, missile if not.
  RAIN       spawned above/around the target and falling, not aimed.
  MULTI      one attack that fires two or more DIFFERENT payload classes.
  SUMMON     spawns live monsters. Factory: MakeSummon.
  BUFF       changes the caster's own stats rather than dealing damage.
             Factory: MakeSelfBuff.
  AURA       a radius effect on everything nearby -- damage OR heal.
             Factory: MakeRadial.

  [SUMMON / BUFF / AURA were ADDED 2026-08-06, part-way through the first
  seventeen-family pass, because the factory layer already had modes for
  all three and the vocabulary did not -- so rows that had a correct
  MakeSummon profile were being forced to read `shape UNCLASSIFIED`. Files
  written before this edit may carry UNCLASSIFIED where one of these three
  belongs; the merge pass must sweep for that specific case rather than
  assume UNCLASSIFIED means "nobody could work it out".]

Frequency in the sample that produced this list (215 states classified of
398 -- the shortfall is the name-filter hole above, so treat these as
proportions, not totals): MELEE 72, SCATTER 57, SINGLE 32, CHARGE 13,
MULTI 12, HITSCAN 12, BURST 7, VILE 6, COMBO 2, FAN 2.


================================================================================
3b. ARG 3 IS NOT AN ANGLE. READ THIS BEFORE ASSIGNING FAN.
================================================================================

Settled 2026-08-06 against the ENGINE SOURCE, not by argument. GZDoom
declares it at E:\UZDXREMA\wadsrc\static\zscript\compatibility.zs:131,
where A_CustomMissile is the deprecated alias of A_SpawnProjectile:

  A_CustomMissile(type, spawnheight = 32, spawnofs_xy = 0, angle = 0,
                  flags = 0, pitch = 0, ptr = AAPTR_TARGET)

    arg 2  spawnheight   how high off the floor it appears
    arg 3  spawnofs_xy   LATERAL OFFSET IN MAP UNITS -- a position, not a
                         direction. Sideways displacement, same heading.
    arg 4  angle         THE ANGLE. Degrees off the monster's facing.

THE RULE THAT FALLS OUT, AND IT DECIDES FAN vs SALVO EVERYWHERE:

  * THREE arguments  -> angle defaults to 0. The rounds fly PARALLEL, from
    offset spawn points. That is a SALVO (or a BURST if spaced in time).
    IT IS NOT A FAN. Reading arg 3 as an angle invents a spread that does
    not exist, and reports a monster firing a cone when it fires a wall.

  * FOUR OR MORE arguments -> arg 4 is a real angle. Stepped values across
    consecutive lines are a genuine FAN and the arc is the span of them.

Worked, both directions:

  A_CustomMissile("RS_TentacleBall2",10,50)
      3 args. Height 10, offset 50 sideways, angle 0. PARALLEL.

  A_CustomMissile("RS_FrostLong2",32,12,-10)
      4 args. Height 32, offset 12, ANGLE -10. Part of a real fan.

Two further traps at the same site, both CH's own text and both to be
recorded verbatim rather than corrected:

  * CH passes CMF_AIMOFFSET (which is 1) into the ANGLE slot at many
    sites, so the "angle" is the integer 1 and the spread is really the
    lateral offset. Found in at least four families.
  * CH passes random(0,360) into the FLAGS slot at other sites, which
    re-rolls the CMF_* bitfield every shot. The behaviour is genuinely
    non-deterministic; say so rather than describing a fixed shape.

================================================================================
4. RULES THAT WILL BE BROKEN IF THEY ARE NOT WRITTEN DOWN
================================================================================

STRIP THE MONSTER'S ANATOMY. `CIMP F 3 A_CustomMissile(...)` contributes
the TIC (3) and the ANGLE (-10). `CIMP F` is imp animation. A revolver has
no CIMP frames. A row that transcribes sprite frames is unusable.

FOLLOW INHERITANCE OR YOU WILL REPORT A LIE. RS_FrostLong2 overrides only
`Spawn`. Its impact puff and DeathSound come from RS_FrostLong and are
written nowhere near the fan. Reading the attack site and the class body
alone reports "no impact FX" for an attack that has one. Open the parent.

NEVER FLATTEN A ROLL. `DamageFunction (random(3,9))` is recorded as
`random(3,9)`. Writing `6` is data loss that hides itself -- no `random(`
is left for anyone to find. This has already cost this project twice
(CLAUDE.md).

IMPACT CAN BE AN ATTACK. RS_CyanImpBall's Death spawns SEVEN more live
RS_FrostLong2 at random(0,359). That is a payload that is itself an
attack -- record it in `impact` AND give the secondary its own row if it
is substantial.

SILENCE IS A FINDING, NOT A BLANK. An attack that plays no sound gets
`sound --` and a note. On a monster that is usually a defect; as a profile
slot it is CORRECT, because the gun's own sound fills it (RS_Weapon's
four-rung chain: affix -> shot -> gun -> catalog default).

CITE FILE:LINE FOR EVERY ROW. A row without a line number cannot be
checked and will not be trusted.

DO NOT CONSULT ANY SOURCE BUT OUR TREE AND CH.

  CH IS AT  E:\New folder\ART SOURCE\CH\  -- VERIFIED ON DISK 2026-08-06.

  CLAUDE.md states the path as C:\Users\Command\Desktop\CH. THAT PATH DOES
  NOT EXIST. That Desktop holds CHP and no CH. CLAUDE.md gives the correct
  path in its own "IMPORTING A MONSTER" section, so the file contradicts
  itself and only one of the two resolves. Use the one above.

  CHP IS NOT CH. Do not substitute it. CHP is a separate pack from an
  earlier abandoned port; reading it as authority is the exact mistake
  CLAUDE.md records for 2026-08-06, when several agents were sent to the
  wrong tree before the owner caught it.

Our tree is what ships. No other pack is authoritative for this project.
If our tree and CH disagree, record BOTH and flag it -- do not "fix"
either.


================================================================================
5. OUTPUT
================================================================================

  docs/monsters/<Family>/<Family>_ATTACKS.md

One file per family. Header: family name, monster count, attack count,
and the denominator you actually read (how many classes, how many states).
Then the rows, grouped by monster.

End every file with an UNRESOLVED section: attacks you could not classify,
payloads whose class you could not find, jumps you could not follow. An
honest gap is worth more than a confident guess -- this project's whole
history is checks that agreed with themselves and were wrong.
