  STANDING FACT THAT DE-RISKS ALL OF E1-E5 (rs_17 s9, [BUILT], verified):
  EVERY GUN IS AN RS_Weapon -- 11 VR_* and 21 RS_GH_*, 32 in total. There
  is no RS_GH_Weapon base class and never was; RS_GH_Weaponset
  (VR_PlayerClasses.zs:212) is a PLAYER class extending VR_DualClassBase,
  which is easy to mistake for one. So the trigger-shape fields land ONCE
  on RS_AttackProfile and every weapon has them -- no second system, no
  parallel dispatch, no per-set port. `set:` is already a live keyword
  filter, so scoping anything to one weapon set is a query, not a refactor.


  E1. PROVE INHERITED STATE LABELS RESOLVE ON THIS ENGINE.
      One weapon, end to end, before touching a second. If they do not,
      rs_17 section 4's landing site is wrong and the whole proposal needs
      rethinking before a single field is added.

  E2. ADD WindupTics + FireOnRelease TO THAT ONE WEAPON.
      Simplest real case is a charge shot. Every proposed field defaults to
      today's behavior, so nothing existing changes.

  E3. ADD BurstCount / BurstDelayTics.
      Retires RS_GH_Pistol's fake state-chain burst and makes its declared
      `trigger:burst` keyword mean something. MUST be documented against
      VolleyCount at the field -- the two will otherwise be confused, and
      someone will build the wrong one or build the second one twice.

  E4. ADD RoFMult.
      Makes an AutoShotgun-style card writable at all, and retires
      RS_GH_Minigun's Overdrive apology comment.

  E5. ADD WindupProfile LAST.
      It carries the recursion hazard. The guard ships in the field comment:
      a WindupProfile's own trigger shape is ignored, always.

  E6. MAKE CANCEL A UNIVERSAL RULE, NOT A FIELD.
      Any windup cancellable by reload or weapon switch, always a full
      refund. One line instead of one field per profile, and it stops a
      20-ammo commitment from being a trap.

  E7. RENAME 19 ProfileName STRINGS.
      All of the form "Gunstar <thing>" -- provenance belongs in the `set:`
      axis, not the display string. Display strings only, no class names or
      includes, so THIS IS THE ONE ITEM THAT CAN JUMP THE COMPILE GATE.

  E8. DERIVE NAMES FOR GENERATED PROFILES FROM THEIR AXES.
      Hand-naming does not scale to rolled profiles; trigger:fullauto +
      archetype:shotgun + payload:multi -> "Auto Buckshot". Hand-name
      authored profiles, derive rolled ones -- two paths, one vocabulary.

  E9. ADOPT THE COVERAGE TEST AS A STANDING PROTOCOL.
      Take a weapon from a feature-rich set, ask "can we build this," roll
      what is missing into an AXIS proposal. The output of a coverage test
      is a GAP LIST, NEVER CODE -- if a session finds itself pasting, it has
      stopped running one.
