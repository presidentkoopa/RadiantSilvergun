build, not before one -- a third unproven change makes a failed build

  E1. PROVE INHERITED STATE LABELS RESOLVE ON THIS ENGINE.
      One weapon, end to end, before touching a second. If they do not,
      rs_17 section 4's landing site is wrong and the whole proposal needs
      rethinking before a single field is added.

  E2. ADD WindupTics + FireOnRelease TO THAT ONE WEAPON.
      Simplest real case is a charge shot. Every proposed field defaults to
      today's behavior, so nothing existing changes.

  E3. ADD BurstCount / BurstDelayTics.
      Retires RS_GH_Pistol's fake state-chain burst and makes its declared
      `trigger:burst` keyword mean something. MUST be documented against
      VolleyCount at the field -- the two will otherwise be confused, and
      someone will build the wrong one or build the second one twice.

  E4. ADD RoFMult.
      Makes an AutoShotgun-style card writable at all, and retires
      RS_GH_Minigun's Overdrive apology comment.

  E5. ADD WindupProfile LAST.
      It carries the recursion hazard. The guard ships in the field comment:
      a WindupProfile's own trigger shape is ignored, always.

  E6. MAKE CANCEL A UNIVERSAL RULE, NOT A FIELD.
      Any windup cancellable by reload or weapon switch, always a full
      refund. One line instead of one field per profile, and it stops a
      20-ammo commitment from being a trap.

  E7. RENAME 19 ProfileName STRINGS.
      All of the form "Gunstar <thing>" -- provenance belongs in the `set:`
      axis, not the display string. Display strings only, no class names or
      includes, so THIS IS THE ONE ITEM THAT CAN JUMP THE COMPILE GATE.

  E8. DERIVE NAMES FOR GENERATED PROFILES FROM THEIR AXES.
      Hand-naming does not scale to rolled profiles; trigger:fullauto +
      archetype:shotgun + payload:multi -> "Auto Buckshot". Hand-name
      authored profiles, derive rolled ones -- two paths, one vocabulary.

  E9. ADOPT THE COVERAGE TEST AS A STANDING PROTOCOL.
      Take a weapon from a feature-rich set, ask "can we build this," roll
      what is missing into an AXIS proposal. The output of a coverage test
      is a GAP LIST, NEVER CODE -- if a session finds itself pasting, it has
      stopped running one.

PART H -- STANDING CONSTRAINTS ON EVERYTHING IN F AND G.
rs_17 section 8. These are not tasks; they are the tests a task must pass.
================================================================================

  H1. NO ELEMENTALS. Stock GunBonsai already owns fire/ice/poison/acid and
      this mod's identity is Doom's own guts. An RS version is kinetic,
      explosive, or a MONSTER SIGNATURE -- say the cut out loud rather than
      quietly shipping a reskin.

  H2. NO DUAL-WIELD BY DUPLICATION. Duplicating a whole weapon for the off
      hand is precisely what the DUAL-WIELD QUARANTINE exists to prevent:
      one-way only, A buffs B never back, no loops, prototype exactly one,
      LAST.

  H3. NEVER RAISE PelletOverride FROM AN IMPORTED SHAPE. It is Promotion's
      own reward lane and the banned move. LIVE INSTANCES TO AUDIT:
      RS_GH_Revolver.zs:61 and RS_GH_SSG.zs:61 both set PelletOverride = 10
      absolutely -- check both against the host's roll before any profile
      work copies the pattern.

  H4. PROFILES MULTIPLY THE HOST'S ROLL; THEY ARE NEVER ABSOLUTE STATLINES.
      Otherwise every shotgun offered the same card becomes the same gun.
      Echo is the precedent -- built from SavedOriginal.Clone(), so an SSG's
      echo and an SMG's echo genuinely differ because the rolls do.

  H5. RUN rs_16'S FIVE-TEST AUDIT ON ANYTHING THAT SURVIVES. Does a rolled
      stat stop mattering (dead) or matter more (best); do two guns now play
      the same (dead); ask similar/opposite/synergistic/antagonistic BEFORE
      coding; never duplicate Promotion's lane.

Kept as an entry rather than a silent edit, because the reasoning is the

  K1. "RETIRE THE IDLE ROTATION MACHINERY" WAS A WRONG OBJECTIVE. CUT.
      rs_17 records that PadTo, InsertAt and Replace have one caller between
      them and calls the rotation layer "built, correct, and idle." That is
      true ONLY of the affix lane -- Echo is indeed the sole affix touching
      slot contents. But Append is load-bearing across the monster roster
      (RS_Baron, RS_Archvile, RS_Arachnotron, RS_ExBosses all build their
      rotations with it), so the machinery is neither idle nor a candidate
      for retirement. Its player-side future use is exactly C5.
      THE GENERAL LESSON, which is the reason this entry exists: a scoped
      observation in a doc reads as a whole-tree claim unless the scope is
      restated. Same disease as rs_16's "the compiler reports one instance
      of a whole-tree defect and stops" -- grep before believing a count,
      and grep before believing an absence.
