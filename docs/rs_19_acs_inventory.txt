================================================================================
   RS_19 -- THE CHP ACS INVENTORY.  2026-08-04.
   What the monster import dropped when it dropped "ACS wrappers",
   how much of it is real behaviour, and what it would cost to rebuild.
================================================================================

WHY THIS DOCUMENT EXISTS
  The owner raised the ACS question repeatedly during the monster import
  and was told each time it did not matter. It does. This file replaces
  that answer with a measured one.

  THE REASONING THAT WAS WRONG, stated plainly so it is not repeated:
  several lanes dropped CH/CHP inventory tokens on the grounds that the
  token's DECORATE body is "a pure ACS_NamedExecuteAlways wrapper with no
  other body, so porting it would import nothing."
  The first half is true. The conclusion does not follow. The wrapper is
  empty BECAUSE the behaviour lives in the ACS script -- that is what the
  wrapper is for. Dropping the wrapper drops the mechanic, and because the
  DECORATE body genuinely does look empty, the loss is invisible at the
  call site and reads as a correct simplification in a code review.

  WORKED CASE -- SpeedBuffPE, the one that surfaced this.
    RS_Cacodemon.zs:351 (Abyss Caco, T06) called
      A_radiusgive("SpeedBuffPE",800,RGF_MONSTERS,1,"Nothin","Caco")
    SpeedBuffPE's whole DECORATE body is
      ACS_NamedExecuteAlways("PESPEED")
    and CHSett.acs:317's PESPEED is:
      bosses exempt; read APROP_SPEED; set ALWAYSFAST; +10 speed;
      hold 600 tics (~17s); restore speed; clear ALWAYSFAST.
    So that state is a PACK SPEED BUFF with a 17-second duration thrown
    to every non-boss monster within 800 units. Not nothing. The Abyss
    Cacodemon's whole tier identity is buffing its neighbours -- its Pain
    state heals them, its Missile state was supposed to hasten them.

================================================================================
THE SCALE -- MEASURED, NOT ESTIMATED
================================================================================

  943 script definitions across CH/source/*.acs and CHP/source/*.acs.
  That number is misleading on its own and should never be quoted alone.

  CHP duplicates each script PER TIER using the colour codes already
  documented in rs_monsternotes (C G B CY P Y A F BR GY R K W KX WX), so
  baronmissile_c ... baronmissile_wx are sixteen copies of one behaviour.
  Collapsing that suffix:

    943 definitions  ->  125 distinct behaviours

  Classified by what the body actually does:

    50   ANNOUNCERS            announce* -- HudMessage + sound on a boss
                               spawn. Cosmetic. CORRECTLY DROPPED.
    36   CH OPTIONS READERS    the whole body is
                               SetResultValue(GetCVar("CH_...")).
                               These exist to expose CH's own options menu
                               to DECORATE. This project has its own
                               MENUDEF/CVARINFO. CORRECTLY DROPPED.
     9   HUD-MESSAGE ONLY      e.g. EXBOSS -- a typed-on screen message
                               plus a Radius_Quake. 246 DECORATE call
                               sites, but the payload is a message and a
                               shake. Cosmetic-plus; the quake is the only
                               real part.
  ** 30   REAL BEHAVIOUR       the list below. THIS is what was lost. **

  So the honest headline is not "943 scripts to rebuild." It is:
  THIRTY distinct mechanics, most of them 5-30 lines of ACS, several of
  which our port already documents as deliberately dropped.

  CAVEAT ON THE 30: the split above is heuristic (it keys off whether a
  body touches SetActorProperty / Give-or-TakeActorInventory / Thrust /
  SetActorFlag / Damage). WVileEXTimer -- 120 lines, the largest script in
  the set and the White Archvile EX's whole timed-phase engine -- landed in
  the HUD bucket because its longest copy is mostly message code. Treat 30
  as a floor, ~35 as the working number, and re-read any script before
  building it.

================================================================================
WHAT THIS MEANS FOR THE PORT
================================================================================

  1. THE DROPS WERE NOT ALL WRONG. 95 of 125 distinct scripts -- the
     announcers, the cvar readers, most of the HUD messages -- are exactly
     the "CHP infrastructure cruft" the port comments call them, and
     dropping them was right. The error is narrower than "the ACS was
     ignored": it is that ONE test ("does the DECORATE body do anything?")
     was applied to a population where it does not discriminate.

  2. EVERY ONE OF THE 30 IS REBUILDABLE IN ZSCRIPT, and most are easier
     there than in ACS. pespeed is a Powerup subclass with a Speed factor
     and a duration -- which also fixes CH's own bug, where the `Nope`
     re-entrancy guard is a script-local that resets every call, so
     repeated buffs stack and drift the base speed. brownrevspeed2's token
     juggling is a single integer field. This is not a port so much as a
     re-expression, and the ZScript version is shorter.

  3. THE PORT ALREADY KNOWS ABOUT MOST OF THEM. Roughly a dozen of the 30
     are named in existing "NOT PORTED (with reason)" headers across
     zscript/monsters/. Those headers are accurate records of what was
     dropped; only the REASON attached to them is wrong. The inventory
     work is therefore mostly already done -- what is missing is the
     decision to rebuild, and the rebuild.

  4. NOTHING HERE BLOCKS THE BUILD. These are absent behaviours, not
     compile errors. The tree compiles without them and the monsters work;
     they are simply less dangerous and less characterful than CH's.

================================================================================
RECOMMENDED SEQUENCING -- NOT STARTED, NEEDS THE OWNER
================================================================================

  Do NOT start rebuilding 30 scripts on the strength of this document.
  The same discipline rs_16 applied to DamageFunction and rs_17 to the
  trigger fields applies here: prove one, then sweep.

    1. Finish the green build first. These are behaviour gaps; a build is
       still the gate.
    2. Rebuild PESPEED as an RS_ Powerup and hang it back on the Abyss
       Caco's Missile.T06. One script, one monster, end to end. It is the
       smallest complete case and it is the one that surfaced this.
    3. If that lands cleanly, do the rest of the PACK BUFF family -- they
       are all the same shape and share one base class.
    4. Missile logic and the Archvile EX timer are their own projects and
       should be scoped separately. WVileEXTimer alone is bigger than
       everything in group 3 combined.
    5. Correct the "porting it imports nothing" comments as each is
       rebuilt, and delete the claim from the headers that still carry it
       (RS_Spectre.zs:64, RS_Revenant.zs:73, RS_demon_projectiles.zs:384).
       Leaving a wrong reason in place is how this survived the first time.
