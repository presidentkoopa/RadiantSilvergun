WHY THIS DOCUMENT EXISTS
--------------------------------------------------------------------------------
The billboard API was a DXR2 addition. DXR2 has been deleted. The engine is now
a fresh clone of upstream questzdoom, and NONE of the billboard surface came
across. Anything written about billboards before 2026-08-06 describes an engine
that no longer exists on this machine. This file is the replacement baseline.

  build     E:\UZDXREMA\build\rs_build.cmd   (log: build\buildlog.txt)

The tree is stock except for TWO CHARACTERS: a missing trailing comma on one row
of wadsrc/static/language.0 (JOYMNU_INVERTDIGITALAXISBUTTONS) and one of
language.csv (CMPTMNU_OLDRANDOM). Both are upstream's own typos. Without them
ParseLanguageCSV reads past the end of the row, copy-constructs an FString from
out-of-bounds memory, and the engine dies on startup with an access violation at
0xFFFFFFFFFFFFFFFC. This is not optional -- stock does not boot on MSVC 14.51.

A dependency fix also lives in build\zmusic\vcpkg.json: its builtin-baseline is
bumped to vcpkg HEAD. At the stock 2023 baseline, yasm's port version reads the
CMake `LOCATION` target property, which CMake 4 removed, and dependency setup
dies before the engine compiles at all.

THE MIRRORING BUG -- ROOT CAUSE FOUND, DO NOT REPEAT IT
--------------------------------------------------------------------------------
On DXR2 the in-world card faced the player correctly but rendered its CONTENT
mirrored. It was described for months as "probably a facing-normal or winding
sign error". It is neither. VERIFIED in this tree:

src/rendering/hwrenderer/scene/hw_sprites.cpp carries TWO UV conventions.

  SWAPPED -- every path that draws a real, asymmetric texture:
     :1654    auto& spi = texture->GetSpritePositioning(0);
     :1658    ul = spi.GetSpriteUR();     <- UR into ul
     :1659    ur = spi.GetSpriteUL();     <- UL into ur

  UNSWAPPED -- exactly one path, ProcessParticle (opens at :1443):
     :1559    ul = vt = 0;
     :1560    ur = vb = 1;

The billboard quad's u runs right-to-left, inherited from the sprite pipeline.
The particle path is wrong in the same way and nobody ever noticed, because
particles are round and a mirrored circle is the same circle. DXR2's BB_TEXTURE
took the particle convention and pointed it at arbitrary textures. Symmetric
content hides it. Text does not.

ANY payload that samples a real texture must follow 1658/1659. Put a comment at
the new site naming the particle path as the trap -- the next person will find
:1559 first, because it is shorter and looks canonical.


OWNER'S REQUIREMENTS FOR THE PLAYER-FACING FEATURE
--------------------------------------------------------------------------------
  1. UNLIMITED PANELS. Not capped in code. A player-facing cap in the options
     menu plus a radial cull from the player. The primitive must tolerate a large
     live set and reject by distance cheaply. This is not a one-panel design.
  2. TWO-STAGE PRESENCE. A dropped weapon always emits a glow and a small light,
     at any distance. The CARD only materialises inside the cull radius. Panel
     existence and drop presence are separate; spawn/despawn on radius rather
     than an alpha fade. Cheaper than holding a panel per drop.
  3. AMBIENT, NOT SUMMONED. The panel appears from the drop, no player input.
  4. ANCHORED TO THE DROP, FACING THE PLAYER. Dies with the actor, engine
     repositions per tic.
  5. HEIGHT MUST NOT BE A FIXED WORLD OFFSET. In VR the eye height is the
     player's real, room-scale height -- not the 41 that Player.ViewHeight
     assumes. DXR2's card sat at +96 against an eye line of 41 and read as far
     too high. A constant cannot be right for every player. Place relative to
     current view z, or expose view z at attach time.
  6. `size` MUST BE DOCUMENTED as half-extent or full-extent. Nobody could
     determine what DXR2 meant. It is the difference between a card 44 tall and
     one 88 tall.


WHAT THE PRIMITIVE HAS TO RENDER (MOD-SIDE SPEC TARGET)
--------------------------------------------------------------------------------
The panel is a SECOND RENDERER for the row model the flat menu already uses. It
does not need to know about weapons, stats or comparison -- all of that is
resolved mod-side and stays there. It needs:

  * a title and a subtitle
  * an ordered list of (label, value, colour) rows -- ONE colour per row, not
    per column
  * eventually, report which row an aim ray hit

Sizing from the built drop triptych: title, subtitle, two header rows, a rule, a
column key, and up to eleven comparison rows -- ~17 rows worst case. Rows that
agree across all three columns are dropped before render, so the common case is
well under that.

Keep the primitive dumb.


THE GATING PROBLEM -- UNSOLVED, AND IT MATTERS
--------------------------------------------------------------------------------
A ZScript call to a native that does not exist is a HARD COMPILE ERROR that stops
the ENTIRE mod loading, not just the feature. That is why the two calls in
zscript/systems/player/rs_ui.zs are commented out rather than branched: RS_Main
would not load at all against the current engine.

ZScript has no #ifdef and no way to test a native's presence at compile time. So
unless someone finds a mechanism, the engine and the pk3 ship as an INSEPARABLE
PAIR, and the mod must state which engine build it requires. Assume that is the
case until proven otherwise.


OPEN DECISIONS -- NOT YET RULED ON
--------------------------------------------------------------------------------
  * Whether the API returns to the DXR2 shape (seven LevelLocals methods, six
    payload enums, three flag bits) or is redesigned. Nothing constrains it now;
    the old shape is a starting point, not a spec.
  * How a canvas texture is identified to a billboard, given TextureID.GetIndex
    is gone.
  * Whether AimBillboard keeps the [hit, uv] multi-return. The owner's stated
    next objective is clickable panels -- aim uv -> row -> netevent -- so if the
    uv is dropped the compositor's row model stops being addressable.
  * RemoveBillboard: never existed on the owner's live DXR2 runtime even though
    AttachBillboard did. Without it a panel cannot be torn down without
    destroying its host actor. Should be in scope.
