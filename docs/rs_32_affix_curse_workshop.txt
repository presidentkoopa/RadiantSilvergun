D1. ReloadSpeed unwired -- RULED per owner, three statements 2026-08-05:
    (a) the stat drives the reload animation by FRAME REPEAT/SKIP in the
    sprite sequence (MODELDEF follows frame letters, model tracks free);
    (b) "clamp the animation not the stat" -- animation multiplier hard-
    clamps [0.7, 1.5], the stat itself never clamps; (c) stat value past
    the animation cap OVERFLOWS into bonus rounds (retune the
    GetReloadBonusRounds coefficient so overflow is real). Two consumers,
    one stat, no dead investment at any promotion count. Also ruled: keep
    ReloadSpeed on the sheet; TimeBetweenShots leaves the sheet (replaced
    by CritMult, R4).
    BUILT 2026-08-05 in-session: RS_Weapon.RetimeReload() rescales each
    reload frame's tics by clamp(ReloadSpeed, 0.7, 1.5) on frame entry,
    per hand -- the fork renders the offhand through its own psprite
    layer (PSP_OFFHANDWEAPON, verified in engine p_pspr.h + exported to
    ZScript), same ticking machinery, so both hands retime identically.
    v1 is retime-only (1-tic frames left alone, not skipped; reload
    frames are 2-6 tics arsenal-wide so the full clamp range expresses).
    GetReloadBonusRounds retuned to the overflow rule: (stat - 1.5) * 4,
    and the shell-weapon incremental path adds the same overflow to its
    free-shell odds. Below 1.5 the stat buys ONLY animation speed --
    bonus rounds unlock via reload cards pushing past the cap, which is
    the ruling, not a regression.
D2. Choke unreachable -- RULED per owner 2026-08-05: "choke should work on
    anything with more than 1 pellet for any reason." Fire-time rule: choke
    factor applies whenever the RESOLVED volley has >=2 pellets (rolled,
    promoted, affix-split, condition-doubled), UsesChoke flag becomes
    derived. Weapons hardcoding Choke=0 get a real roll. Task rechipped.
    (G3's PATTERN PLATE affix is obsoleted as a functionality-grant -- the
    baseline now grants it; only its Mastery idea, distance-adaptive cone,
    survives as a possible card.)
D3. A_RS_Backfire asymmetry -- FIXED 2026-08-05 (owner confirmed it was
    killing him in play). Was raw DamagePerShot: per-PELLET on shotguns
    (5-12 self-hit), per-ROUND on heavies (110-320 crit-doubled). Now reads
    a quarter of the resolved volley (DamagePerShot * PelletCount * 0.25):
    SSG ~25-60, launcher ~27-40 (54-80 crit) -- one survivable band, price
    proportional to the shot's worth. The 0.25 is the tuning knob.
D4. Condition degradation unwired -- BUILT 2026-08-05 per owner directive
    ("weapons need to be able to degrade due to damage, def when standing in
    a hazard for sure"). zscript/systems/weapon/RS_Condition.zs +
    RS_ConditionHandler (MAPINFO-registered): (1) player damage -> both
    equipped weapons via OnPlayerDamaged (numbers stay in RS_Roll: 20+ hit
    -> -3); (2) damaging floors grind rs_condition_hazard_rate (1.0/sec)
    while grounded; radsuit dial rs_condition_hazard_suited (0=seals guns,
    0.25 default, 1=no shielding) per the owner's "or even if radsuit?"
    follow-up. Master switch rs_condition_degrade. Grey Bits and the sub-50
    gamble band are now live content.

Also recorded: RS_Bit_Curse actor EXISTS in RS_Bits.zs (line ~396), drop roll
stubbed with `false &&` at line ~173. Cursebits are one word from live.

1. HARD IMPLEMENTATION FACTS (bind every design below)
--------------------------------------------------------------------------------
- ModifyDamageDealt / Tick / OnProjectileCreated reach the MAINHAND bag only.
  Hand-correct hooks: OnDamageDealt, OnKill (RS graft), and the shot resolver
  RS_ShotKeywordMods.Resolve (best hook: runs both hands, every mode).
- Per-tic player reads need a helper Inventory granted OnActivate (DoEffect).
- A_RS_FireSlot resolves keywords BEFORE NotifyFired stamps RS_LastFiredWeapon
  (RS_Weapon.zs ~476 vs ~502). At resolve time the field = PREVIOUS shot's
  weapon = the cross-hand signal. Load-bearing ordering; comment both sites.
- There is NO monster tier system in code. Live difficulty ladder =
  SpawnHealth(), gates already picked by RS_Score: fodder <150, giant >=700
  (rs_score_giantslayer_hp). Never invent a second ladder.
- SetPieces do not exist in code. Anything gated on them is held, not approximated.
- Score is a walled currency (RS_Score.zs header law). Anything converting
  score/streak into damage/economy needs an explicit owner ruling. (Conflict C1.)
- Budget law (rs_09): +/-30% net DPS at L5 unconditional; ~+55% if condition
  live under half the time; up to ~+90-110% only for genuine emergencies.
- Never static const arrays; switch chains. New .zs files go in zscript.txt.

  absence (player can tell it's idle). Properties whose ONLY hook is map
  furniture (barrels, crushers, telefrags, secrets) belong in RS_Score as
  bonuses, not on weapons.

7. ELITE DROP SYSTEM -- OWNER RULINGS (2026-08-05, consolidated)
--------------------------------------------------------------------------------
The drop is a DATA PACKAGE, not a weapon actor (post-set-completion). The six
class weapons are permanent chassis; a package applies to one of them via the
compare card. Package carries: Tier, Damage, Accuracy, Velocity, CritChance,
Capacity, Condition, ReloadSpeed, RateOfFire, magazine, attack pattern.
Chassis keeps: PelletCount, PromotionCount, GunBonsai level/XP/upgrades.
(RoF/reload animation changes obey the clamp-the-animation rule, D1.)

R1. SET COMPLETION ORDER: before the set is complete, elite drops ARE the
    missing class weapons, fixed sequence _2 -> _5 -> _3 -> _6 (alternating
    mainhand/offhand), rolled stats, default attack profile. Tier pool
    Cursed/Trash/Basic until all six owned.
R2. AFTER COMPLETION: full ladder Cursed->Prototype, weighted by the eight
    rs_elite_dropweight_* sliders (defaults descending), +0/1/2 tier-bonus
    slider applied post-roll capped at Prototype. All drops random family.
    Killed before the 50% reveal = no drop, ever.
R3. THE CARD: cannot be banked -- but a rejected package DOES NOT despawn;
    it stays in the world. Third option on the card: RECYCLE for gold (or
    points), paying MORE for higher-tier cards you turn down.
R4. TWELVE STATS -- RULED (owner, 2026-08-05): TimeBetweenShots is REMOVED
    from the sheet (was derived-only in code anyway) and CRITMULT takes its
    slot as the twelfth stat. Rolled per tier (shape: Basic ~1.8-2.4x,
    scaling to ~4-5x top rolls at Prototype), rides with the data package,
    and replaces the hardcoded 2.0 at the fire dispatch. Crit becomes a
    two-dice moment: CritChance rolls whether, CritMult rolls how hard.
    Feeds/is fed by: Momentum (streaks), EXECUTIONER (raises it), GLASS
    HAMMER (trades base damage for it), and the per-pull-vs-per-pellet
    crit imbalance (G5) now has a real stat to resolve against. Reserved
    (ex-Divinity) remains the sheet's one open slot.
R5. CURSED PACKAGES (PROVISIONAL -- owner explicitly unsure, revisit):
    up to X curses per Cursed package; each LIFTED curse raises the weapon
    ONE TIER, max Prototype. Makes Cursed the only package whose tier can
    GROW -- the long-game gamble vs. the instant clean high-tier card.
    Open math: Cursed->Prototype through the full ladder is 7 steps; X and
    whether lifts skip the junk tiers are both undecided. Cursebit earn
    model (section 3) remains proposed, not yet ratified.
R6. C11 Pink raise-exclusion REVERTED to source behavior: only fellow C11
    corpses and clones are unraisable; other elite corpses are fair game.
    (Applied in RS_EliteColors.zs same day.) Violet's -130.0 stays as
    preserved source behavior until ruled otherwise.
R7. BULLET TIME (owner ruling 2026-08-05): NOT a SetPiece requirement.
    It arrives later as a USER-TOGGLEABLE option, consent-gated, default
    OFF -- the owner is explicitly cautious about time dilation without
    player opt-in (VR comfort). Every encounter (incl. the Captain
    SetPiece and its 2x escalation) must be fair and beatable with it
    off; toggled on, it layers onto the same fight beats as an
    enhancement. An existing bullet-time mod will be integrated for the
    dilation itself when the time comes.
