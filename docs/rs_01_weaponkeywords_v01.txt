================================================================================
                  RADIANT SILVERGUN -- KEYWORD SCHEMA v1
================================================================================

--------------------------------------------------------------------------------
THE TWO RULES
--------------------------------------------------------------------------------

RULE 1 -- A keyword is a permanent fact about a weapon CLASS.
If you can only learn it by inspecting one specific weapon instance, it is a
stat, not a keyword. It already lives on RS_Weapon and has a real field.

    NOT KEYWORDS (live instance data, already implemented):
      Tier, Condition, DamagePerShot, Accuracy, Velocity, CritChance,
      Capacity, PelletCount, GunBonaiSockets, Choke, XP, Level,
      PromotionCount, which curse rolled, which stat is locked

RULE 2 -- If a tag is true for every entry, it is not a tag.
An axis earns its place only when it splits the roster. Any keyword that
reads the same on all ten weapons is decoration and gets cut.


--------------------------------------------------------------------------------
SYNTAX
--------------------------------------------------------------------------------

    key:value                      space-delimited, flat
    key:value key:value2           multi-value = repeat the key
    NO nested values               (kills curse:locked-stat:accuracy)
    lowercase, hyphen-separated    one convention, no exceptions

Multi-value keys (may repeat):   trigger, element, behavior, grip, curse, fun
Single-value keys (exactly one): archetype, delivery, payload, feed, reserve,
                                 growth, promo, socket, set, model


--------------------------------------------------------------------------------
BASE vs GRANTED -- the mechanism that makes "any gun we haven't thought of"
--------------------------------------------------------------------------------

Keywords exist in two layers:

  BASE      authored on the class. Never changes. Ships with the weapon.
  GRANTED   added at runtime by a GunBonsai affix, a promotion, or a socket.

Eligibility checks query the UNION of both. This is the whole trick: affixes
can grant the same keywords they gate on, so affixes chain into each other and
produce weapons nobody designed.

    WORKED EXAMPLE -- emergent gun

    Basic Revolver, as authored:
        archetype:revolver delivery:hitscan payload:single element:kinetic

    + affix "Ballistic Conversion"   (no requirement)
        GRANTS delivery:projectile   -> now routes through RS_BallisticFired
        -> homing / ricochet / forking affixes are now ELIGIBLE

    + affix "Fragmentation"          (requires delivery:projectile)
        GRANTS payload:cluster

    + affix "Thermal Core"           (requires delivery:projectile)
        GRANTS element:thermal

    + 3 Promotions                   PelletCount 1 -> 4
        AUTO-GRANTS payload:multi
        -> choke / spread affixes are now ELIGIBLE

    Result: a 4-pellet projectile cluster thermal revolver.
    No designer authored that weapon. The schema made it expressible.

NOTE: promotion auto-granting payload:multi is why PelletCount stays live data
and payload stays a keyword. The count is per-instance, the CATEGORY is queryable.


================================================================================
GROUP A -- IDENTITY  (the normalization layer)
================================================================================

archetype:      THE closed set. This is the "60 imported guns collapse to 15
                categories" axis. An imported Minigun is tagged
                archetype:chaingun and every system treats it as a chaingun.

    revolver  pistol  smg  rifle  shotgun  supershotgun  chaingun
    launcher  energy  bfg  melee

    Extensible, but deliberately curated. Adding a value is a decision,
    not a reflex.

set:            Origin. DORMANT -- record-keeping only, gates nothing yet.
                Reserved so import-specific behavior stays possible later.

    radiantsilvergun  vanilla  brutal  doom4  wolf3d  pirate  <mod-name>

model:          MODELDEF binding key. Feeds the model-swap-on-promotion idea
                and any future third-party model assignment tooling.

    vr_revolver  vr_pistol  vr_smg  ...  vanilla  none


================================================================================
GROUP B -- FIRE MECHANICS  (what the trigger does)
================================================================================

trigger:        Implemented. These are literally two different code paths in
                RS_Weapon (CanFireSemiAuto vs AutoCooldownReady).

    semi-auto     release required between shots, cadence overshoot penalised
    full-auto     held trigger, hard cooldown gate on RateOfFire
    burst-3       fixed burst per pull
    charged       hold to build, release to fire
    wind-up       spool before first shot
    held-beam     continuous while held
    bolt-action   manual cycle between shots
    pump          manual cycle, shotgun-flavoured

grip:           Requested feature. Gates the offhand-barrel stabilise mechanic
                (which is goofy on one-handed guns).

    one-hand      revolver, pistol, smg
    two-hand      everything else
    stabilizable  offhand grip tightens spread -- usually paired with two-hand

cadence:        RESERVED, NOT YET EARNING ITS KEEP.
                rhythm-punished is real and implemented (GetCadenceOvershoot),
                but right now it correlates 1:1 with trigger:semi-auto, and
                cooldown-hard correlates 1:1 with trigger:full-auto. Per RULE 2
                this axis is decoration until a weapon breaks the correlation.

    rhythm-punished   firing faster than cadence costs Accuracy  [IMPLEMENTED]
    rhythm-rewarded   hitting cadence exactly boosts damage      [not built]
    spooling          sustained fire ramps rate                  [not built]
    cooldown-hard     rate is an absolute gate                   [IMPLEMENTED]


================================================================================
GROUP C -- DELIVERY  (what leaves the barrel)
================================================================================

delivery:       The single most useful axis for affix gating. Homing, ricochet,
                forking, orbiting -- none of them mean anything on a hitscan.

    hitscan     A_FireBullets path
    projectile  RS_BallisticFired path -- real travel time, Velocity matters
    beam        continuous, instant, no travel
    lobbed      arcs under gravity
    wave        expanding front
    radial      omnidirectional burst from impact

payload:        Category, not count. Count is live data (promotion changes it).

    single      one projectile per shot
    multi       many per shot -- Choke becomes meaningful
    slug        single heavy, shotgun-family
    explosive    area damage on impact
    cluster     splits into submunitions
    hazard      leaves a persistent zone

element:        Base damage flavour. Affixes grant additional elements; a
                weapon can carry several at once.

    kinetic  thermal  corrosive  shock  plasma  void

    CUT: divinity-legacy. The overview says Divinity was removed. Dead reference.

behavior:       In-flight modifiers. Almost always GRANTED by affixes rather
                than authored on a base weapon.

    ricochet  piercing  homing  forking  orbiting  stick-delay  wall-runner


================================================================================
GROUP D -- FEED & ECONOMY
================================================================================

feed:           Strongly discriminating -- six distinct values across ten
                weapons. Any affix touching reload needs this, and four
                weapons have no reload at all.

    speedloader   all chambers at once            (revolver)
    magazine      full mag at once                (pistol, smg, rifle)
    per-shell     one at a time, interruptible    (shotgun)
    break-action  both barrels together           (supershotgun)
    belt          no reload, straight from reserve(chaingun)
    cell-direct   AmmoUse straight from reserve   (launcher, energy, bfg)
    none          does not consume ammo           (melee)

reserve:        The pool it draws from. All vanilla types per current design.

    clip  shell  rocket  cell  none  self-recharging

cost:           Weak axis -- currently only splits BFG (40 cells) and launcher
                from everything else. Keep only if more expensive weapons appear.

    standard  expensive  free

ammo-source:    FEATURE, NOT CLASSIFICATION. These tags imply systems that do
                not exist yet. Tag nothing with them until the system is built.

    blue-bit         standard                              [exists]
    red-bit          spends player HP per shot             [NEEDS SYSTEM]
    grey-bit         spends Condition for extreme damage   [NEEDS SYSTEM]
    self-recharging  regenerates over time                 [NEEDS SYSTEM]

bit-synergy:    Same warning. Roster reserved, systems unbuilt.

    gold-eater       spends Gold Bits for guaranteed crits  [NEEDS SYSTEM]
    green-converter  excess armour becomes ammo             [NEEDS SYSTEM]
    grey-thirsty     drains Condition faster, hits harder   [NEEDS SYSTEM]


================================================================================
GROUP E -- GROWTH, PROMOTION, SOCKETS
================================================================================

promo:          What this weapon class gains on Promotion. Genuinely varies --
                the overview specifies "+1 Pellet (or +X pellet for shot-
                weapons)", so shotguns are mechanically distinct here.

    pellet-duplicator  +1 pellet per promotion      (single-payload weapons)
    pellet-multiplier  +X pellets per promotion     (shotgun family)
    stat-retainer      smaller raw-stat loss on promotion
    socket-expander    promotion grants a socket instead of a pellet
    ceiling-breaker    larger stat-ceiling gain than standard

socket:         What KINDS of affix this class accepts. Not how many -- socket
                COUNT is tier-driven live data.

    universal  offensive-only  utility-only  elemental-only  none

growth:         WEAK AXIS -- currently every weapon would read "standard".
                Keep the vocabulary, but do not author it until weapons
                actually differ in XP curve.

    fast-learner  standard  stubborn


================================================================================
GROUP F -- CURSES  (separate set, per design)
================================================================================

Which curse a weapon HAS is live instance data. The ROSTER of curses that can
exist is static, so the roster lives here.

curse:
    bit-repellent    Bits drift away from the player instead of toward
    gold-drain       kills yield no Gold while equipped
    jam-prone        elevated backfire chance independent of Condition
    loud             every shot alerts monsters at double radius
    fragile          Condition degrades at double rate
    heavy            movement speed penalty while equipped
    blind            no crosshair / no hit feedback
    hungry           consumes double reserve ammo per shot
    silent-partner   offhand weapon cannot fire while this is equipped

    NOTE: locked-stat is NOT here. WHICH stat got locked is per-instance
    (LockedDamage / LockedAccuracy / ... already exist as real fields).


================================================================================
GROUP G -- ANOMALY  (late-game, rule-breaking)
================================================================================

anomaly:
    vampiric      damage dealt converts directly into Red/Green Bits
    necromantic   slain enemies burst into temporary Bit hazards
    mirrored      offhand copies mainhand's firing pattern
    echo          every Nth shot fires again, free
    parasitic     drains stats from the weapon in the other hand

    CUT: quantum ("fires simultaneously from both hands"). This breaks the
    independent left/right hand model that the entire arsenal, the class
    system, and the offhand Gun Bonsai XP fix are built on. Not a keyword
    problem -- an architecture collision. Revisit only if dual-hand
    independence is ever deliberately abandoned.


================================================================================
GROUP H -- THE FUN ONES
================================================================================
Unrestricted except that it has to be DOOM. These are affix-granted, never
authored on a base weapon.

--- Ties into THIS mod's own systems -------------------------------------------

    glow-reactive       reads the room's active glow channel colour and shifts
                        behaviour to match it. Neon-red room, thermal damage.
                        Green room, corrosive. Uses the custom shader as an
                        actual gameplay input. No other Doom mod can have this.
    tier-sighted        damage scales against monsters above or below a tier
                        threshold -- a weapon that only wakes up for real threats
    tier-hunter         gains XP only from monsters at or above your weapon tier
    bit-magnet          widened auto-collect radius on all Bits
    promo-greedy        gains double XP but loses double raw stats on promotion
    dakka-fed           damage scales with the live combo/score multiplier
    swan-song           enormous boost while at critical health
    bone-dry            enormous boost while reserve ammo is empty
    switch-hitter       bonus damage on the first shot after a hand swap
    setpiece-bound      only reaches full power during a purchased SetPiece

--- Pure Doom -----------------------------------------------------------------

    berserk-sympathy    scales with Berserk active
    infighting-instigator hits can make the target blame a nearby monster
    barrel-sympathetic  explosive barrels in radius cook off on hit
    nukage-powered      repairs Condition while standing in damaging floor
    gib-fed             gibbing an enemy refunds ammo
    telefrag-capable    point-blank kills count as telefrags
    archvile-proof      corpses killed by this cannot be resurrected
    lost-soul-magnet    pulls flying enemies toward the impact point
    cyber-slayer        bonus damage vs boss-tier, penalty vs fodder
    icon-scale          damage scales with the target's max health
    pain-locked         hits never stagger -- or always do
    crusher-safe        immune to being destroyed by map hazards
    door-opener         shots can trigger switches and open doors at range
    rocket-jump-rated   self-damage reduced, self-knockback increased
    rad-shielded        grants radsuit behaviour while equipped
    plasma-buffer       the famous buffer bug, weaponised on purpose
    chainsaw-tether     pulls the target toward you on hit
    soulsphere-fed      overheal converts into weapon XP
    secret-sniffer      audible ping near undiscovered secrets
    slaughter-tuned     scales with live monster count on the map
    hundred-percent     scales with kills/items/secrets completion
    pistol-start-blessed stronger the fewer weapons you carry
    tyson-honor         massive bonus if no ammo weapon has fired this map
    map-eater           consumes automap knowledge for a temporary power spike
    doomguy-grin        the HUD face reacts specifically to this weapon's kills
    blue-key-hungry     stronger while carrying keys
    demon-fear          low-tier monsters flee instead of approaching

    socket      universal 7 / offensive-only 2 / elemental-only 1

MEDIUM (real but thin, revisit as the roster grows):
    trigger     only 2 values in use -- but they are genuinely different
                code paths, so it stays
    element     kinetic 8 / plasma 2 -- weak now, becomes strong the moment
                elemental affixes exist
    cost        standard 8 / expensive 2 -- borderline

WEAK (vocabulary reserved, do NOT author yet):
    cadence     correlates 1:1 with trigger -- decoration until something
                breaks the correlation
    growth      every weapon reads "standard" -- violates RULE 2 today

DORMANT (record-keeping, gates nothing):
    set         reserved for future import-specific behaviour
    model       reserved for model-swap-on-promotion and import tooling

BLOCKED (tag nothing until the system exists):
    ammo-source, bit-synergy
