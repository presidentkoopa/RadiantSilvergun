// taken, damage dealt, score thresholds; per-level floors and caps).
// MUST precede RS_ScoreRevival.zs, which references RS_LifeInfo.
//
// This file existed on disk for a full compile cycle without this line,
// and the result was four "Unable to resolve RS_LifeInfo as a type"
// errors that stopped the whole mod loading -- the exact trap CLAUDE.md
// documents: a .zs that is not in this list SILENTLY DOES NOT EXIST.
// RS_LivesHandler MUST be in MAPINFO.txt's AddEventHandlers, and it is.
//
// This comment previously said the opposite -- that a StaticEventHandler
// "registers itself, so it deliberately does NOT go in MAPINFO". That was
// my assumption and it is FALSE. EventManager::InitStaticHandlers
// (E:\UZDXREMA\src\events.cpp:590-622) builds the handler list from
// exactly two places: gameinfo.EventHandlers and the per-map
// Level->info->EventHandlers, both of which are MAPINFO. There is no
// self-registration path for any handler type.
//
// The cost of believing it: the ENTIRE lives system was dead code.
// Nothing granted RS_LifeForce, so its AbsorbDamage hook was never
// installed -- no lives earned, none spent, no death saves, no fire
// cone, and every rs_lives_* cvar and menu row inert while looking
// perfectly alive. The exact failure this project keeps hitting: no
// error, no warning, just a system that silently is not there.
